# Field Sampling

Field sampling applies one propagation model to a deterministic sequence of
sample positions and returns an immutable result snapshot.

This milestone connects existing grid generation and propagation calculation
without adding rendering, visualization, multiple sources, or application
state.

## Module And Package

Field sampling belongs in the `rf-simulation` module under the
`com.rfsimulator.simulation` package.

The implementation may depend on `rf-domain` and `rf-scene`. It must not
depend on JavaFX, application state, rendering code, visualization code, or
persistence.

## Inputs

The planned sampler accepts:

- a `RadioSource` describing the source to sample;
- a `PropagationModel` used to calculate received power;
- an ordered sequence of `Position2D` sample positions.

Passing `null` for the source, model, sample collection, or any sample position
should throw `NullPointerException`.

The sampler should not create grid points itself. Grid definition and point
generation remain separate responsibilities owned by `RectangularGridDefinition`
and `GridPointGenerator`.

## Output

The planned output is an immutable simulation-result snapshot containing the
sampled values in order.

Each sample result should preserve:

- the `Position2D` sample position;
- the calculated `PowerDbm` received power at that position.

The result snapshot should preserve the same ordering as the input sample
positions. This keeps the relationship between generated grid points and
sampled powers deterministic and easy to test.

## Empty Input

An empty sample-position sequence is valid.

Sampling an empty sequence should return an immutable result snapshot with no
samples. It should not throw an exception merely because there is no work to
perform.

## Failure Behavior

The sampler should fail fast.

If the propagation model throws for any sample position, the sampler should let
that exception propagate rather than skip the sample, invent a value, or return
a partial result. This keeps invalid model inputs visible and avoids hiding
source-position singularities.

For the current `FreeSpacePathLossModel`, a sample exactly at the source
position throws `IllegalArgumentException`. A sampling operation that includes
the source position should therefore fail with that exception.

## Immutability

Sampling results must be immutable snapshots.

Callers should not be able to mutate the result by changing the original input
collection after sampling. Callers also should not be able to mutate the
snapshot's internal sample list after receiving it.

The contained domain values are already immutable. The result snapshot's main
responsibility is to preserve list ownership and ordering.

## Responsibilities

Field sampling does:

- iterate over sample positions in deterministic input order;
- call one `PropagationModel` for each sample position;
- store each position and calculated received power in an immutable snapshot.

Field sampling does not:

- define rectangular grid bounds;
- generate grid points;
- choose or implement propagation equations;
- combine multiple radio sources;
- normalize values for display;
- choose colors or legends;
- render heatmaps or source markers;
- run calculations in the background.

## Expected Behavior

Given identical source, model, and ordered sample positions, the sampler should
produce identical ordered result snapshots.

For sample positions generated by `GridPointGenerator`, the sampled result order
should match the generator order exactly.

## Suggested Test Cases

Tests should cover:

- null source throws `NullPointerException`;
- null model throws `NullPointerException`;
- null sample collection throws `NullPointerException`;
- a null sample position throws `NullPointerException`;
- empty sample collection returns an empty immutable result;
- sampled result count matches input sample count;
- sampled result order matches input sample order;
- each result stores the original sample position and calculated `PowerDbm`;
- changing the original input collection after sampling does not change the
  snapshot;
- attempting to mutate the snapshot's exposed sample list fails;
- a model exception for one sample propagates to the caller.

## Current Scope

This milestone should sample one source with one propagation model over an
ordered sequence of positions.

Multiple sources, source-combination rules, model selection, visualization
normalization, JavaFX rendering, and background execution belong to later
milestones.
